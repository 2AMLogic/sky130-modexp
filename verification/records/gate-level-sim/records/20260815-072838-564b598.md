# Record 20260815-072838-564b598

- **Record ID**: 20260815-072838-564b598
- **Claim**: `spec/modexp.md`'s Correctness row (*"bit-exact vs `pow(b, e,
  m)`, randomized, on every commit"*) re-established against the **routed
  layout** rather than the RTL, and `docs/baseline.md#post-route-gate-level-simulation`.
  Substantiates issue #9's Leg 1 (zero-delay gate-level equivalence).
  **Does not** substantiate #9's Leg 2 (delay-annotated simulation at the
  corner set) — recorded below as blocked on upstream tooling, with
  evidence, not silently skipped.
- **Design provenance**: layout (post-P&R, extracted) — the netlist under
  test is **derived from `layout/modexp.gds` itself**, not from any netlist
  handed to P&R. Chain:
  `layout/modexp.gds` → (issue #8's `klt extract --abstract-cells`)
  `layout/lvs/modexp_layout_abstracted.spice` →
  (`verification/gate-level/spice_to_verilog.py`)
  `verification/gate-level/modexp_post_route.v`. **718 instances / 59
  distinct cell types / 68 top-level pins / 770 signal + 444 power-pin nets
  = 1214 nets**, every one of those figures cross-checked against
  `layout/lvs/modexp_layout_extract_report.json` before the run was allowed
  to proceed. This is deliberately *not* #7's
  `modexp_synth_tied.v` (683 instances + 1 tie cell), which is the netlist
  fed **into** P&R and omits the 35 CTS/timing-fixup insertions and 5
  drive-strength resizes #8 attributed instance by instance.

     netlist (with `--check`, so a disagreement with the extraction report
     aborts before any simulation), links the resolved PDK cell models, then
     runs `klt functional-verification
     verification/gate-level/request-modexp-gate-level.json --format json`.
     Engine `icarus` 12.0, cocotb 2.0.1, timescale `1ns/1ps`,
     `random_seed: 1`. Testbench `test_modexp` — the committed
     `verification/test_modexp.py`, **unmodified**, reached through a git

     --compare-rtl verification/records/width-cross-check/artifacts/20260808-031948-5488082/width-16.jsonl`

     unmodified through cocotb's own `Runner` (klt's request schema has no
     compile-time-defines field; see "klt provenance").

    + `primitives.v`, compiled with `` `define FUNCTIONAL `` and

    corners but exactly one, corner-independent set of Verilog cell models.
    A zero-delay functional run therefore has no corner attribute at all;
    corner dependence enters only through SDF, which is the blocked leg.

  (7 directed vectors + 40 randomized at `random_seed: 1`, exactly what the
  committed `test_modexp.py` contains — no reduction). Leg 1b is N = 500
  randomized cases at `WIDTH=16`, drawn from `random.Random(20260807016)` —
  the *same* pinned seed derivation `verification/cross_check.py` uses, so
  the vector stream is identical to the recorded RTL `width-16` run's.
  0-mismatch pass/fail, not a distribution claim.

  - **Leg 2 — delay-annotated simulation at the corner set: NOT ACHIEVED,
    blocked on upstream tooling.** Two independent, verified blockers,
    transcript at `artifacts/20260815-072838-564b598/leg2-blocker-evidence.txt`:
    1. **No artifact carrying post-route delays exists.** `klt
       place-and-route`'s response contract is `def_path` + `gds_path`
       only — no `write_sdf`, no netlist; and `klt
       functional-verification`'s request schema has no SDF option
       (`_resolve_options` returns `coverage`, `timescale`, `random_seed`).
       Both read directly off the installed pinned package. Filed upstream
       as [klayout-tools#1002](https://github.com/2AMLogic/klayout-tools/issues/1002)
       (open). This blocker is simulator-independent and cannot be worked
       around inside this repo without driving OpenROAD outside `klt` — which
       would in any case yield delays for a *re-routed* design, not for the
       committed, DRC/LVS-checked `layout/modexp.gds`.
    2. **The available simulator cannot run the annotatable models.** Icarus
       12.0 rejects `-ginterconnect` (`Unknown/Unsupported Language
       generation interconnect`, exit 255 — it is an Icarus 13 flag), and
       with or without `-gspecify` emits 620 × `warning: Timing checks are
       not supported and delayed signal "<pin>_delayed" will not be driven`,
       after which the whole design simulates as `x`. Control in the same
       transcript: the identical netlist and directed vector
       (`2**10 mod 1000`) returns `16'b0000000000011000` = 24 under the
       `FUNCTIONAL` models and all-`x` under the timing models. Filed
       upstream as [klayout-tools#1004](https://github.com/2AMLogic/klayout-tools/issues/1004).
  - **No mismatch or timing failure was observed anywhere in the legs that
    ran**, so there is no failing vector to report.
  - **What this run does not model**, restated as load-bearing scope (same
    caveats #8 documented for LVS, plus what is simulation-specific): **no
    parasitic extraction** (no R/C/coupling; `klt extract` was run without
    `--parasitics`, nothing here reads a SPEF), **no timing** (the only delay
    is the 1 ns `UNIT_DELAY` on flop outputs, a race-avoidance device rather
    than a characterized delay — no setup/hold check is exercised), **no
    corner**, **no power/ground network** (power pins dropped; this GDS has
    no PDN, so extracted rail connectivity is fragmented across 444 nets),
    **cell-instance granularity, not transistor level**, and **not an
    independent check of the extraction itself** (extraction and simulation
    share `klt extract`'s output as a common input).
