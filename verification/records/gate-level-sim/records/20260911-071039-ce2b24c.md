  - **A pin-promotion refinement was needed to regenerate the extraction
    correctly, beyond what issue #81's own record used**: an unrestricted
    `klt extract --abstract-cells ... --def-net-names` extraction
    over-promotes every internal, DEF-net-named net to top-level-pin status
    (`pin_count` **756**, not the correct **70** — the real 68 functional
    I/O pins + `VDD`/`VSS`), which `spice_to_verilog.py`'s `parse_spice()`
    would otherwise take at face value, emitting ~585 bogus top-level output
    ports. `klt extract`'s own `--def-pins <path-to-def>` (upstream
    klayout-tools#1390) is the documented fix for exactly this failure mode
    — it restricts pin promotion to the routed DEF's own genuine `PINS`
    section (`layout/modexp.def`, 70 entries: the 68 functional I/O +
    `VDD`/`VSS`, confirmed directly against the DEF). **Verified
    LVS-neutral**: the two extractions' `X`-card instance bodies are
    byte-identical with or without `--def-pins` (diffed sorted, zero
    differences) — only the `.SUBCKT modexp` header's declared-pin list
    differs, so this does not reopen or alter issue #81's own LVS
    mismatch-count finding. See `layout/lvs/README.md`'s "Update (issue
    #83...)" section for the full note.
  - **A second, independent bug was found and fixed while regenerating**:
    `--def-net-names` can also label an *internal* (non-port) net as a bus
    bit, e.g. `mm_p[3]` — `spice_to_verilog.py` previously declared one
    `wire mm_p[3];` per bit instead of grouping them into a single ranged
    `wire [hi:lo] mm_p;`, which Icarus parses as a SystemVerilog
    unpacked-array declaration of a *different* size per bit, failing
    Icarus elaboration with `'mm_p' has already been declared in this
    scope`. Fixed by grouping internal bus-bit net names into ranged `wire`
    declarations the same way top-level port buses already were (`ports()`).
    Covered by a new synthetic fixture case
    (`case_internal_bus_grouping`), independent of the `VDD`/`VSS` fix.
  - **A third, independent bug (JSON-schema drift, not a `klt` defect) was
    found and fixed**: `layout/lvs/modexp_layout_extract_report.json`'s
    `nets[].name` field is now written SPICE-escaped (`\$1568`, matching
    `klt`'s own `NetlistSpiceWriter` node-reference spelling, schema_version
    3 / klayout-tools#1162) rather than the older plain `$1568`
    `spice_to_verilog.py`'s `check_against_report` was written against.
    Fixed by re-deriving the report's own escaping convention
    (`report_net_spelling`) before comparing, rather than assuming the
    unescaped form. Documented and intentional upstream behavior (verified
    against `klayout_tools/extract.py`'s own `escape_net_name` docstring),
    not a friction-protocol candidate.
