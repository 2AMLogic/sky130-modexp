  **klt's own verdict** (`sdf-sim-response.json`, `artifacts/`): request
  error class `SDF back-annotation ... did not fully apply`, 203 diagnostics
  in the Icarus transcript. Per-transcript breakdown (`test_icarus.log`,
  frozen in `artifacts/`):
  - **200 `SDF ERROR: ... Could not find intermodpath!`** — every one an
    `INTERCONNECT` statement where one endpoint is a **top-level module
    port** (`base_in[N]`, `exp_in[N]`, `mod_in[N]`, `result[N]`, `done`),
    never a purely internal instance-pin-to-instance-pin interconnect (those
    all resolve). Confirmed independently: a hand-driven `iverilog -gspecify
    -ginterconnect -s klt_sdf_annotate -s modexp` build against the same
    sources reproduces the identical failure class (`Error: Could not find
    net. Did you run iverilog with '-ginterconnect'?` at runtime, despite the
    flag being present at compile time).
  - Every one of those 200 failing entries carries `(0.000:0.000:0.000)` in
    the SDF itself — i.e. even a fully successful annotation of them would
    have contributed **zero** delay. This looks like a genuine Icarus
    `$sdf_annotate` limitation resolving a primary-port-attached
    `INTERCONNECT` target specifically (as opposed to a leaf-instance pin),
    not a `klt`-side authoring defect — `klt`'s SDF diagnostic gate is
    conservative *by design* (any unresolved entry fails the run, regardless
    of whether it would have mattered for timing) precisely so a partial
    annotation is never silently reported as a full one.
  - 130 `SDF WARNING: ... TIMINGCHECK not supported` — the pre-known, exempt
    (`SDF_BENIGN_DIAGNOSTIC_SUBSTRINGS`) class; every cell's setup/hold check
    section, not implemented by Icarus, delays themselves unaffected.

  **The regression's own values, independently corroborating a real
  problem** (not merely `klt`'s gate being conservative): both the directed
  test (`test_modexp_known_vectors`, `modexp(2,10,1000)`) and the randomized
  test (`test_modexp_random`, `modexp(25247,55125,55342)`) report `got 0` —
  a uniform, constant-zero result across every case, not an occasional
  single-bit mismatch consistent with a marginal setup/hold violation. This
  pattern is consistent with a broken control-path signal (the 200 failing
  interconnects include `done`), not with subtle real-delay timing failure;
  root-causing this precisely (rather than the diagnostic-gate failure
  above, which is sufficient on its own to fail the run) is not attempted in
  this record.
