  **Two disclosed deviations from a bare `klt lvs` invocation**, both
  forced by tool gaps filed upstream, neither touching the design:

  - *The reference netlist is a mechanically rewritten copy, not the
    frozen file itself.* `klt lvs`'s Verilog reader accepts only a plain
    `assign <net> = <net>;` and rejects a concatenation right-hand side;
    `modexp_synth_tied.v` carries exactly three, all of them Yosys's
    normal rendering of a vector assignment
    (`assign mm_p2 = { mm_p, _tie_zero_ };` and two siblings).
    `layout/lvs/expand_concat_assigns.py` expands those three into 51
    per-bit plain `assign`s and copies every other line through byte for
    byte; the result is committed as `layout/lvs/modexp_synth_expanded.v`.
    Verified directly: every non-`assign` line of the two files is
    identical (`diff` over both files with `assign`/comment lines
    filtered — no output), so no module port, `wire` declaration or cell
    instantiation differs. All three rewritten nets (`mm_p2`, `mm_m1`,
    `mm_m2`) are additionally **dead** in the frozen netlist — zero
    bit-select references from any cell instance — so the expansion
    cannot change the compared connectivity even in principle. The frozen
    evidence file under `verification/records/` is not edited. Filed
    upstream, generically:
    [klayout-tools#2372](https://github.com/2AMLogic/klayout-tools/issues/2372).
  - *The netgen binary was reached through a `PATH` shim.* `klt lvs`
    invokes the netgen engine as the literal name `netgen`; Ubuntu's
    `netgen-lvs` package installs it as `/usr/bin/netgen-lvs` (the name
    `netgen` there belongs to an unrelated FEM mesher), so leg 2 was run
    with a directory containing `netgen -> /usr/bin/netgen-lvs` prepended
    to `PATH`. The binary itself is the stock distribution build, netgen
    1.5.133, unpatched. Filed upstream, generically:
    [klayout-tools#2373](https://github.com/2AMLogic/klayout-tools/issues/2373).

- **Result**: **the top-level LVS verdict is still `status: "mismatch"` —
  T1 item 4 is still `unmet`** — but two of the three things this record
  set out to establish now hold, and the residual is smaller and named.

  | Leg | Engine | Reference form | `status` | `mismatch_count` | `error_count` | `power_connectivity.status` |
  |---|---|---|---|---|---|---|
  | 0 (control) | `klayout` | `plain-element` | `mismatch` | 17 | 17 | `unchecked` |
  | 1 (committed) | `klayout` | `gate-level-verilog` | `mismatch` | 13 | **12** | **`match`** |
  | 2 (cross-check) | `netgen` 1.5.133 | `gate-level-verilog` | `mismatch` | 3 | 2 | **`match`** |

  - **Leg 0 reproduces the recorded 17 exactly** (`category_counts:
    {"topology": 17}`), on a klt three pins newer than the one
    `20260911-053500-d5e43d3` used. So the whole 17 → 12 change in leg 1
    is the reference form, not tool drift.
  - **Power connectivity is `match`, over all 3074 placed instances**
    (`power_pins: ["VGND", "VPB", "VPWR"]`, `findings: []`,
    `finding_count: 0`). The pin universe is derived by klt's own
    `declared-by-every-instantiated-master` rule across 47 masters, with
    `corroborated: true` — not a hardcoded name list. The check runs
    *before* the filler/tapcell prune below, by design, so the 2352
    physical-only instances' power connectivity is inside this verdict
    rather than excluded by it. `VNB` is absent from the pin universe
    because the committed abstracted extraction resolved no `VNB` pin on
    any master (zero occurrences in
    `modexp_layout_abstracted.spice`) — an extraction-coverage fact about
    that netlist, disclosed here rather than read as a clean verdict on a
    pin nothing checked. **What this verdict is** is per-instance
    pin-to-net consistency: every master's `VGND`/`VPB`/`VPWR` pin reaches
    the same net every other instance's same-named pin reaches. **What it
    is not** is geometric rail continuity or an IR-drop result; those stay
    `klt erc` / `klt power` territory (`layout/erc/` carries this block's
    supply-island evidence separately).
  - **The five physical-only masters are gone from the mismatch list, by
    the tool's own hand and with disclosure.** Leg 1 carries a
    `severity: "warning"`, `category: "topology.power_only_pruned"` entry
    naming exactly `SKY130_FD_SC_HD__FILL_1`, `__FILL_2`, `__FILL_4`,
    `__FILL_8` and `SKY130_FD_SC_HD__TAPVPWRVGND_1` — the five types whose
    every declared pin is a power/ground pin of the reference library, and
    which therefore cannot have a synthesis-side counterpart by
    construction. This is `klt lvs`'s native
    `_prune_power_only_layout_circuits` behaviour for a
    `gate-level-verilog` reference, not a filter this repo applied. Note
    the prune stops where the evidence does: the antenna-fixup master
    `SKY130_FD_SC_HD__DIODE_2` declares a non-power `DIODE` pin and is
    **not** pruned — it stays in the error list below.
  - **The 12 remaining `topology` errors are the P&R logic transform, and
    nothing else.** All 12 are
    `"circuit could not be matched to a counterpart"`: 10 `side:
    "layout"` masters absent from the pre-CTS reference
    (`BUF_4`, `BUFINV_16`, `CLKINV_2`, `CLKINV_4`, `INV_1`, `INV_6`,
    `NOR2_2` — CTS/timing-fixup insertions; `DIODE_2` — antenna fixup;
    `O21AI_2`, `O22AI_2` — post-resize drive strengths), 1 `side:
    "reference"` (`O22AI_1`, the pre-resize drive strength the routed
    layout no longer instantiates), and 1 `side: "both"` (the top
    `MODEXP` circuit, cascading from the above). Still zero
    `net.split`/`net.merged`/`device.*` on the klayout engine. This is the
    same residue the 2026-09-11 records attribute instance-by-instance
    against the DEF (680 identical name+type, 3 resized, 35 fixup
    insertions, 0 synthesis instances missing) — unchanged, and now the
    *whole* remaining gap rather than one part of it.
  - **Second-engine cross-check: run, and it concurs — `mismatch`, not
    `match`.** netgen 1.5.133 reaches a different, deeper failure mode
    than `NetlistComparer` does: where the klayout engine stops at the
    circuit-type level, netgen proceeds to instance/net partitioning and
    reports `device.unmatched` + `net.unmatched`, whose raw side-by-side
    fragments (embedded verbatim in `mismatches[].details.raw`) show the
    structural reason — every layout-side instance carries
    `VGND`/`VPB`/`VPWR` terminals that the signal-only gate-level
    reference has no counterpart for, so netgen's fanout-class refinement
    cannot converge. **The two engines agree on the verdict and disagree
    on the diagnosis**; neither reports a match. That is the honest form
    of a cross-check here — it removes "one toolchain agreeing with
    itself" as an explanation for the mismatch, and it independently
    confirms that nothing in this comparison is silently passing.
  - **`body_verification.status` is `"unchecked"`** in both legs, with the
    reason klt states verbatim: the pre-extracted `layout.netlist` request
    form carries no deck, so nothing distinguishes a drawn body tie from a
    synthesized one. Recorded, not read as `"verified"`.
  - **What would make leg 1 `status: "match"`, and why it is not reachable
    here**: the reference would have to be the *as-built* post-route
    netlist (CTS buffers, antenna diodes and resized cells included), not
    the pre-CTS synthesis netlist. `klt place-and-route` did write one —
    `verification/records/place-and-route/artifacts/20260911-052542-d5e43d3/par-nominal-output.json`
    records a `verilog_path` alongside the `def_path`/`gds_path` that
    produced the committed layout — but only the DEF and GDS were
    committed from that run, and issue #55 established that re-running
    `klt place-and-route` against the identical frozen
    netlist/floorplan/seed does **not** reproduce `layout/modexp.gds`
    (722 vs 718 instances). So no as-built netlist for *this* GDS exists
    in the tree and none can be regenerated. Deriving one from
    `layout/modexp.def` would make the compare self-referential against
    the same DEF the extraction already took its net names from, which is
    a materially weaker claim than it would sound like — deliberately not
    done here. Tracked as
    [sky130-modexp#139](https://github.com/2AMLogic/sky130-modexp/issues/139)
    rather than forced.
