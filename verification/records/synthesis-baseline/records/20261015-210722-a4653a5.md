# Record 20261015-210722-a4653a5

- **Record ID**: 20261015-210722-a4653a5
- **Claim**: issue #195 -- isolate why `klt synthesize flow/synthesize-modexp.json`
  gives 717 instances under klt 0.6.0 where `20260808-032045-5488082`
  recorded 682. **The cause is the klt version, not the PDK and not the
  Yosys build**: klt 0.6.0 generates a different Yosys script than klt 0.2.0.
  No cross-lab comparison of any kind is made (`docs/baseline.md`, the
  overclaim rule). This record changes no figure; it attributes one.
- **Design provenance**: rtl (`rtl/modexp.v` @ a4653a5bc55d831509ee8c5535ba2fcf2ad39a96), `WIDTH=16`
  (module default), content_hash unchanged from the earlier records.
- **Run configuration**: the same committed request (`flow/synthesize-modexp.json`,
  unconstrained, `sky130_fd_sc_hd` / `tt_025C_1v80`) run with
  `PDK=sky130A PDK_ROOT=~/.volare` (`open_pdks c6d73a35...`) and the same
  `yosys` on `$PATH` (host Yosys, reported by klt as `0.67+post`), changing
  **only the klt version**, each in a throwaway venv under `flow/build/iso/`
  (gitignored):
  1. `klayout-tools==0.2.0` (PyPI)
  2. `klayout-tools` at the pinned `dac2b5daceb6` (`0.6.0+gdac2b5daceb6`)
  Then an ablation of the klt 0.6.0 Yosys script, one flag group removed at a
  time, run directly with `yosys` (table in `ablation.md`).
- **Statistical convention**: N/A (deterministic synthesis).
- **Result**:
  - klt 0.2.0: **682** / 6877.8464 um^2 (reproduces `20260808-032045-5488082`).
  - klt 0.6.0: **717** / 7144.352 um^2 (reproduces `20261015-205100-4d8d397`).
  - **Attribution -- klt, via its generated Yosys script.** Diffing the two
    scripts (modulo paths) klt 0.6.0 adds three things to the flow:
    `abc -constr` (a file with `set_driving_cell sky130_fd_sc_hd__buf_1` and
    `set_load 5`), `abc -dont_use sky130_fd_sc_hd__lpflow_* -dont_use sky130_fd_sc_hd__probe*`,
    and `setundef -zero` + `hilomap` to `sky130_fd_sc_hd__conb_1` tie cells.
  - **Ablation** (full table in `ablation.md`): without `-constr` and
    `-dont_use` the klt 0.6.0 script gives 686 / 6892.8608, which is exactly
    682 cells + 4 `conb_1` tie cells (4 x 3.7536 um^2 = 15.0144 um^2 =
    6892.8608 - 6877.8464). `-constr` alone accounts for roughly +31-33
    cells (output-load-aware abc sizing/buffering: `buf_*`, `clkbuf_1`,
    upsized `_2` variants appear); `-dont_use` alone is ~+/-2 (719 with it
    removed vs 717 with it).
  - **Not a regression in the design**: same `rtl/modexp.v` hash throughout,
    and the PDK liberty deck hash is the same as in both earlier records.
    The 717 figure is the cost of the klt 0.6.0 flow (constraint-aware
    mapping plus explicit tie cells), not of a changed RTL.
  - **Caveat on the Yosys build**: this matrix ran the host `yosys` for both
    legs (0.67+post), not the pinned `yowasp-yosys==0.68.0.0.post1208`. That
    is deliberate -- it is the *same* binary in both legs, so it cannot explain
    the delta -- and `20261015-205100-4d8d397` independently showed 717 under
    both the pinned wasm and the host build. The old-Yosys-with-0.6.0 leg of
    the issue's matrix was therefore unnecessary and not run.
  - **Overall: PASS for the claim this issue owns** (cause isolated). 682
    remains the klt-0.2.0-flow figure; 717 is the figure for the pinned
    toolchain (`scripts/setup-env.sh`).
