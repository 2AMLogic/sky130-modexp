# Record 20261028-190000-8b4112d

- **Record ID**: 20261028-190000-8b4112d
- **Claim**: issue #271 (T1 item 5, kernel gate) -- does the radix-2 carry-save
  Montgomery **kernel** (DR-0011's P1) reach 100 MHz at `ss_n40C_1v28` once
  DR-0011 follow-up (1) is applied (pre-registered operand AND, fan-out-limited
  quotient control)? Finding: **no.** Best kernel misses by 1.635 ns. Per the
  issue's gate the complete datapath is **not** built. Nothing here changes the
  committed design, `layout/`, or any T1 verdict.
- **Design provenance**: `rtl/modexp.v` @ `8b4112d` is the committed design and
  is untouched. P1 is the frozen DR-0011 kernel
  (`artifacts/20261027-120000-98bf55d/candidates/rtl/p1-*.v`); P4 and P5 are new
  timing-probe kernels frozen under
  `artifacts/20261028-190000-8b4112d/candidates/rtl/`.
- **Run configuration**: per kernel, one run of
  `artifacts/20261028-190000-8b4112d/candidates/tools/eval.sh` (byte-identical
  to record `20261027-120000-98bf55d`'s harness): `klt synthesize` with
  `flow/synthesize-modexp.json` -> `flow/tie_constants.py` -> `klt
  place-and-route` with `flow/par-modexp.json` (tt corner, 100 MHz, seed 42) ->
  `klt sta` at the single corner `ss_n40C_1v28`, period 10.0 ns. Tools are the
  repo pin built into a throwaway venv in the worktree: `klayout-tools==0.8.0`,
  `yowasp-yosys==0.68.0.0.post1208` (`yosys.wasm` sha256 verified against
  `docs/environment.md`), `ciel` PDK `open_pdks f6eeac7`. Single-corner runs
  only; the 18-corner sweep was **not** run because no kernel reached the point
  where it would be informative.
- **Statistical convention**: deterministic single runs (P&R seed 42). P1 was
  re-run under this pin to separate the design change from the tool change: it
  reproduced DR-0011's number to the printed digit (-2.44823 ns), so the
  P1->P4 delta is attributable to the RTL, not the klt 0.7.1->0.8.0 move. No
  repetition across seeds, so placement variance for P4/P5 is **not**
  characterized.
- **Result**: **The kernel does not close; item 5 stays `unmet`; the complete
  design is not built.** Binding corner `ss_n40C_1v28`, setup, 100 MHz target
  (`f_max = 1/(10 - WNS)` as `klt sta` reports).

  | id | kernel | WNS (ns) | f_max (MHz) | instances | self-check |
  | --- | --- | --- | --- | --- | --- |
  | P1 (re-run) | DR-0011 kernel, unchanged | -2.448 | 80.33 | 420 | existing |
  | P4 | P1 + operand AND pre-registered + q computed per 4-column group | -1.635 | 85.95 | 403 | 2000 random odd moduli at W=8 and W=16, 0 errors |
  | P5 | P4 + per-group duplicated S0/C0/B0 flops (`keep`) | -4.431 | 69.30 | 402 | same, 0 errors |

  Hold slack is +2.59 ns in every run; `timing_status` is `constrained`.

  - **P4 gains 0.81 ns over P1 and still misses by 1.635 ns.** Pre-registering
    `a0*b` removes the operand-AND level from the q path, as intended.
  - **The fan-out duplication did not take effect.** In P4 and P5 the worst path
    still goes through one net of fan-out 45-46 (`results/p4-worst-path.txt`,
    `results/p5-worst-path.txt`): Yosys/ABC merged the per-group q copies (and,
    in P5, the duplicated flops) back into one driver despite `(* keep *)`, then
    the flow's own `place*` buffering decided the tree. P5 is worse because
    the merged net is then driven by a single `a21oi` with no buffer before
    its 46 sinks (4.03 ns on that one stage). So the DR-0011 follow-up (1)
    lever "duplicated control" is **untested as a design idea**; what was
    measured is that this flow does not let RTL force it.
  - P4 worst path (9.78 ns arrival, 1.86 ns setup): flop clk-to-Q 2.20 ->
    `maj3` 3.03 -> `a21oi` 1.02 -> fan-out-45 `buf_4` 1.82 -> `and3` 1.51 ->
    `nor3` 0.20. After the flop (2.20 ns), the data
    budget is 5.94 ns (10 - 1.86 setup - 2.20); the q reduction (`maj3`,
    `a21oi`) plus the fan-out buffer take 5.87 ns of it, leaving the mask and
    merge gates (`and3`, `nor3`, 1.71 ns) 1.64 ns over.
  - Not built, and therefore not claimed: R^2 mod m, carry-save->binary
    conversion, final reduction, a modexp cocotb suite, a cycle count. No
    supersession of record `0001` Decision 3 is proposed (nothing priced).
