- **Why these numbers are not corner-for-corner comparable to
  `20260816-072918-d8eafca`** (stated up front so no reader silently reads a
  delta into them): the two differ in **both** the thing measured and the
  way it is measured.
  1. **Different layout.** This record analyses the committed
     `layout/modexp.def` — `flow/par-modexp.json`'s 35% utilization /
     `core_margin_um` 4 floorplan **with** issue #81's `power` block (265
     tapcells, a real met1/met4/met5 PDN, 2087 filler cells, 4 antenna
     diodes). That record analysed eighteen layouts built from
     `flow/run-corner-sweep.sh`'s 55% / `core_margin_um` 2 floorplan with
     **no** `power` block.
  2. **Different methodology.** That record ran one full
     `floorplan→place→cts→route` build *per corner*, so each corner's
     numbers include that corner's own `repair_timing` fix-up buffering
     (e.g. 798 instances at `ss_n40C_1v28` vs 716 at `tt_025C_1v80`) — a
     table of eighteen designs. This record re-times **one** fixed geometry,
     optimized only at the nominal corner, at all eighteen. A slow corner
     therefore reads *worse* here by construction, because nothing was
     re-optimized for it. `klt sta` (klayout-tools#1099) is what makes the
     single-geometry form possible at all; it did not exist when that record
     was minted.
  3. **Different parasitic basis from the in-flow P&R STA.** `klt sta` with
     `spef` omitted times the design against the parasitics OpenSTA derives
     from the loaded LEF/DEF alone, whereas `klt place-and-route`'s own
     in-flow STA runs `estimate_parasitics -global_routing` first. This is
     why the nominal corner reads WNS **+4.367 ns / 177.53 MHz** here
     against the **+3.736 ns / 159.63 MHz** record `20260911-052542-d5e43d3`
     reports for the same DEF. **That is a methodology difference, not an
     improvement** — the unannotated numbers in this table are optimistic
     relative to the routing-estimated ones, and the gap at the binding
     corner is understated, not overstated, by the same token.
- **Limitations of this evidence, explicitly**:
  - **No SPEF / no extracted parasitics.** `request.spef` was omitted (see
    point 3 above). Feeding `klt extract --parasitics` output in would need
    the net-name-correlation problem issue #55 already evidenced
    (`verification/records/drc-lvs/records/20260816-174310-5e656e5.md`) to
    be solved first; that is out of this record's scope.
  - **No hold-side WNS/TNS at this pin.** `klt sta`'s response at
    `f77036bf...` carries `hold_violation_count` but no hold-side slack
    figure — already filed and fixed upstream
    ([klayout-tools#1625](https://github.com/2AMLogic/klayout-tools/issues/1625),
    fixed by [#1634](https://github.com/2AMLogic/klayout-tools/pull/1634)),
    in commits later than this repo's pin. No new upstream report is
    warranted; a future pin bump gets the field for free.
  - **Ideal, not propagated, clock**, and an extrapolated rather than
    bisected `fmax_mhz` — both documented limits of `klt sta`'s own first
    version (`docs/cli/sta.md`, "Not corner-searched or propagated-clock
    timing (yet)").
  - **This is STA, not simulation.** Per-corner *functional* evidence is a
    separate leg and remains as recorded: zero-delay gate-level Leg 1 passes
