# Record 20261028-220000-c681034

- **Record ID**: 20261028-220000-c681034
- **Claim**: issue #271 (T1 item 5, kernel gate, DR-0014 "next lever: logic
  depth per cycle") -- does either depth lever, a 4:2-compressor datapath
  (P10) or a recoding of the radix-2 addend set that removes one 3:2 level
  (P11a-c), bring the radix-2 carry-save Montgomery **kernel** to 100 MHz at
  `ss_n40C_1v28`? Finding: **no.** Every working kernel lands at 82-85 MHz,
  1.8-1.9 ns short of 10 ns, within the ~1 ns noise floor of the best prior
  kernel (P8, 85.00 MHz). The binding term is the quotient recurrence
  (q -> q'), not the 3:2 depth. The complete datapath is **not** built. Nothing
  here changes the committed design, `layout/`, or any T1 verdict.
- **Design provenance**: `rtl/modexp.v` @ `c681034` is the committed design and
  is untouched. P8 is the frozen kernel of record `20261028-210000-a65f037`.
  P10, P11a, P11b and P11c are new timing-probe kernels frozen under
  `artifacts/20261028-220000-c681034/candidates/rtl/`, named `modexp` only so the committed
  `flow/` requests apply (probe interface, not the modexp handshake).
- **Run configuration**: per kernel, one run of
  `artifacts/20261028-220000-c681034/candidates/tools/eval.sh` (byte-identical to record
  `20261028-210000-a65f037`'s harness): `klt synthesize` with
  `flow/synthesize-modexp.json` -> `flow/tie_constants.py` -> `klt
  place-and-route` with `flow/par-modexp.json` (tt corner, 100 MHz, seed 42,
  default `WIDTH=16`) -> `klt sta` at the single corner `ss_n40C_1v28`, period
  10.0 ns. Tools are the repo pin in a throwaway venv in the worktree:
  `klayout-tools==0.8.0`, `yowasp-yosys==0.68.0.0.post1208` (`yosys.wasm`
  sha256 matches `docs/environment.md`), `ciel` PDK `open_pdks f6eeac7`.
  Single-corner runs only; the 18-corner sweep was **not** run. `klt` was
  driven throughout; Yosys was never run directly. The self-check testbench
  `tools/tb_kernel_1cycle.v` gained a parameter `X` (extra cycles between the
  load and the first iteration, default 0, so P8/P10 are checked exactly as
  before); P11a uses `X=1`, P11b/P11c use `X=WIDTH/2+1`.
- **Statistical convention**: deterministic runs. P10 (best new kernel) was
  re-run identically (WNS -1.80254 ns, bit-for-bit the same as the first run)
  and with P&R seed 7 via `tools/eval-seed.sh` (WNS -1.80253 ns). As in record
  `20261028-210000-a65f037`, the placer seed does not move this flow's result;
  variance across *netlist* perturbations is still not characterized, and
  differences under ~1 ns are within noise (record `20261027-120000-98bf55d`).
- **Result**: **No kernel closes; item 5 stays `unmet`; the complete design is
  not built.** Binding corner `ss_n40C_1v28`, setup, 100 MHz target
  (`f_max = 1/(10 - WNS)` as `klt sta` reports). P8 from the prior record is
  repeated for comparison.

  | id | kernel | WNS (ns) | f_max (MHz) | instances | self-check |
  | --- | --- | --- | --- | --- | --- |
  | P8 (prior record) | six q copies, shallow q recurrence, two chained 3:2 | -1.764 | 85.00 | 428 | 2000 odd moduli, W=8/16, 0 errors |
  | P10 | P8 with a 4:2 compressor per column (xor2 tree + horizontal cout/cin) | -1.803 | 84.73 | 411 | same, 0 errors |
  | P11a | one 3:2 level, addend `q ? v : u` with `v = a_i ? b+m : m`; `b+m` added in ONE prep cycle | -13.845 | 41.94 | 781 | same (X=1), 0 errors |
  | P11b | P11a with `b+m` added 2 bits/cycle over `WIDTH/2` prep cycles (b, m rotate), six q copies | -1.875 | 84.21 | 637 | same (X=WIDTH/2+1), 0 errors |
  | P11c | P11b with four q copies (no async-set flop) | -1.854 | 84.36 | 623 | same (X=WIDTH/2+1), 0 errors |

  Hold slack is +2.4 to +2.5 ns in every run; `timing_status` is
  `constrained`.

  - **P10 (4:2 compressor) is no change.** The worst path is the same shape as
    P8's (flop 2.19 -> `maj3` 3.08 -> `xnor2` 1.46 -> `nor2` 0.65 -> `o31a`
    2.66, the q recurrence into a q copy). The six q-copy endpoints are
    -1.80 ... -1.11 ns; the datapath endpoints behind them are at -0.56 ns
    (P8: -0.63), so the 4:2 structure bought about 0.07 ns of datapath depth,
    below the noise floor. (`results/p8-endpoint-slacks.txt`,
    `results/p10-endpoint-slacks.txt`.) Whether Yosys/ABC kept the xor2 tree
    was not traced; the mapped worst path contains no `xor3`.
  - **P11a measures the adder, not the kernel.** The one-cycle 16-bit `b+m`
    ripple (flop -> and2 -> nor2 -> ... -> `o311a` chain -> `a211o`) is 22.13
    ns of arrival. It is reported for the record that a prep add cannot be one
    cycle; it says nothing about the kernel.
  - **P11b/P11c take the add off the cycle, and pay for it.** A 4-bit chunk was
    tried first and put three chained `maj3` (3.0 ns each) on the path (WNS
    -5.41 ns, not frozen); 2 bits per cycle fits. The price of this recoding is
    `WIDTH/CH + 1` extra cycles per Montgomery product (9 extra on 16 at
    `CH=2`, i.e. no throughput gain can come from this form without a cheaper
    way to form `b+m`), and 2W+1 extra flops (instances 623-637 vs 428).
    That price is a property of the probe as built, not a priced proposal;
    no supersession of record `0001` Decision 3 is made.
  - **P11b's worst path starts at an async-set q copy** (`dfstp_2`, 4.97 ns
    clk-to-Q at this corner, vs ~2.2-2.4 ns for the reset flop), which
    confounds the depth measurement. P11c replaces the six copies by four
    (polarity x {async-reset, none}) so no async-set flop remains. The result
    moves only 0.02 ns (-1.854 vs -1.875 ns): the copy-flop kind was not the
    limit.
  - **P11c worst path** (arrival 10.10 ns, setup 1.75): flop 2.42 -> `mux2i`
    1.81 (addend bit 1, selected by q) -> `xnor3` 2.54 -> `and2` 0.98 -> `o31a`
    2.37 (load mux) into a q copy: **the quotient recurrence again**. The four
    q-copy endpoints are -1.85, -1.85, -1.49, -1.37 ns; the S/C datapath
    endpoints are at -0.96 ns (`results/p11c-endpoint-slacks.txt`). The
    recoding removed a 3:2 level but moved a q-selected mux in front of the
    one that remains; the datapath is no shallower than P10's.
  - **Q fan-out stays small.** The worst-path flop fan-out is 4-5 in P10 and
    P11b/c, and the largest input-pin fan-out of any non-clock/reset net in
    the four synthesized netlists is 10 (script count over the netlist, not
    q-specific).
  - **What the endpoints say about the lever.** In P8, P10 and P11c the
    binding endpoints are the q copies, and the datapath is 0.6-1.1 ns
    behind them. Making the datapath one level shallower (P11c) did not
    move the q-copy endpoints, because q' = S1^C1^add1^(S0|C0)^x_r with
    add1 = q ? v1 : u1 has q in its own input cone. Observation, **not
    measured**: the q-independent part A = S1^C1^(S0|C0)^x_r can be formed
    before q is known and q' = q ? (A^v1) : (A^u1), which leaves only a
    mux2 on the q loop. No probe of that form exists in this record.
  - Not built, and therefore not claimed: R^2 mod m, carry-save->binary
    conversion, final reduction, a modexp cocotb suite, a cycle count, an
    18-corner sweep, parasitic-basis comparison. The kernel self-check relies
    on an odd modulus (Montgomery precondition, as in P1/P4/P8).
