# Record 20260924-134500-1a8313b

- **Record ID**: 20260924-134500-1a8313b
- **Claim**: issue #141 — a **re-derivation attempt** of record
  `20260923-093000-28a7c96`'s candidate **row 6**
  (`candidates/06-bit-serial-cell-exclusion-ss-par/`), now that its one
  blocking dependency has landed upstream, run end-to-end through
  **committed, re-runnable `klt` requests** for the first time.

  Two results, stated separately because they are independent:

  **Result A — the reproducibility blocker is discharged.** The 209-cell
  standard-cell exclusion that row 6 needed is now expressible as a
  `klt synthesize` request field (`constraints.dont_use`, upstream
  [klayout-tools#2429](https://github.com/2AMLogic/klayout-tools/pull/2429)
  closing [klayout-tools#2382](https://github.com/2AMLogic/klayout-tools/issues/2382)).
  `klt synthesize` driven by the committed request in this record's
  artifacts produces a netlist **byte-identical** (`sha256:f33ededc…`) to
  the one the frozen hand-rolled Yosys script
  (`…/20260923-093000-28a7c96/candidates/yosys-cell-exclusion.ys`) produces
  when run directly on the same host. DR-0004 Decision 1(a)'s **first**
  ground for not landing row 6 no longer applies.

  **Result B — row 6's 18/18 does not reproduce.** The same recipe, run
  end-to-end on this host, closes at **17 of 18** ratified corners, with
  `ss_n40C_1v28` at setup slack **−0.574 ns / 94.57 MHz**. Row 6's frozen
  measurement was **+0.489 ns / 105.14 MHz / 18 of 18**. DR-0004 Decision
  1(a)'s **second** ground — that row 6's closure verdict is
  methodology-marginal — is therefore not merely still live but has
  resolved *against* closure: both available STA methods now agree the
  binding corner does not close (see "Result" below).

  **This record makes no claim about `layout/modexp.def`.** The routed
  layout measured here was produced in the gitignored `flow/.klt/` scratch
  tree and is deliberately not committed. The committed layout, its
  DRC/LVS/gate-level evidence, and `verification/signoff/block-manifest.json`'s
  T1 item-5 citation (record `20260923-093000-28a7c96`, 10/18 at
  22.80 MHz) are all unchanged by this record.

  The in-flow figure reproduced to within 0.06 ns of row 6's. The `klt sta`

  **Root cause of the divergence — measured, not inferred.** The mapped
  netlist has **1105 instances / 10158.4928 µm²**, where row 5/6 recorded
  **1204**. This is *not* a difference between the new request field and
  the frozen hand-rolled script: run on this host, the two produce the same
  netlist byte for byte (`sha256:f33ededc…`), and the generated `abc` line
  is flag-for-flag identical in the same order. It is also not a Yosys
  *version* effect: Yosys 0.67 and 0.68 give identical results here. The
  remaining explanation is the **ABC build embedded in the Yosys binary**
  differing between this host and the one row 6 was produced on — i.e. the
  frozen row-6 netlist is not reproducible across hosts at all, by the
  committed request *or* by its own frozen script.
